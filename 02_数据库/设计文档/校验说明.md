# 数据库设计校验说明

已完成以下结构校验：

- JSON 数据字典包含 33 张表；
- ER 总图包含 33 个实体定义；
- 数据字典包含 64 组外键；
- ER 总图已渲染为 PNG 和 SVG；
- `DENTIST_PERFORMANCE` 已连接 `DENTIST`、`CLINIC` 和审核账号 `ACCOUNT`；
- 预约、排班和改约字段使用 `DATETIME`；事件字段使用 `TIMESTAMP`；业务日期使用 `DATE`；
- 所有枚举字段均有独立状态字典；绩效结果保存计算口径版本和计算时间；
- 未定义退款表、工资表、奖金支付表、利润表、成本表或会计总账表；
- OpenDental 原始 XML 保留在 `参考资料`，用于追溯，不改写原始参考文件。
- 已生成覆盖 33 张表和 64 组外键的 `sql/00_schema_postgresql18.sql` 逻辑建表基线。
- 建表基线包含 35 条由 PostgreSQL 18 执行的 `CHECK` 约束，覆盖枚举、时间顺序、金额/数量非负和绩效计数一致性。
- 绩效唯一键为 `dentist_id + clinic_id + period_start + period_end + calculation_version`，同一周期可保留不同口径版本。
- ID 策略确定为 PostgreSQL identity，不使用 UUID；预约改约、库存扣减和收款重复提交规则已写入并发控制说明。

业务状态、时间区间冲突、结算金额一致性和绩效指标口径仍需要在实现阶段使用数据库约束、事务和服务层校验共同保证。
