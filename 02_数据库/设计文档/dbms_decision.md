# 物理数据库方言决策

## 当前决定

逻辑模型保持数据库方言中立；物理 SQL 以 PostgreSQL 18 作为实现目标。OpenDental XML 的 MySQL 风格字段只用于理解参考，不决定 ADC 的最终数据库方言。

## 实现要求

- 数据库编码使用 UTF-8；
- 金额使用 `DECIMAL(12,2)`，禁止使用浮点金额；
- 数量使用 `DECIMAL(12,3)`；
- 预约、排班和改约时间使用 `TIMESTAMP WITHOUT TIME ZONE`，业务时区固定为 `Asia/Shanghai`；
- 创建、审核、付款和审计时间使用 `TIMESTAMP WITH TIME ZONE`；
- 业务日期使用 `DATE`；
- 单字段 ID 使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`；
- 复合主键表不生成 identity 列；
- `CHECK`、唯一约束和外键由 PostgreSQL 18 直接执行；
- `CREATE TABLE` 可以先创建全部表，再统一创建外键。

## ID 和 UUID 的简单决定

本项目不使用 UUID。你不需要自己填写 ID，也不需要理解 UUID。

- 普通主键由 PostgreSQL 自动递增生成；
- 业务编号仍然通过唯一键保存，例如患者统一编号、治疗项目编码和收款凭据号；
- 预约、诊所、牙医等关系使用自动生成的数字 ID；
- 如果未来需要多数据库离线同步，再重新评估 UUID，不影响当前设计。

## 并发控制的简单决定

并发控制就是防止两个人同时修改同一个预约或库存时互相覆盖。

- 改约时，在同一个事务中锁定原预约和目标排班，再确认目标时段未被占用；
- 库存扣减时，使用 `lock_version` 或 PostgreSQL 行锁，保证库存不会扣成负数；
- 收款时使用唯一 `request_no`，重复提交返回原结果，不重复收款；
- 绩效结果按牙医、诊所、统计周期和口径版本设置唯一键，避免重复生成。

本项目当前交付的是逻辑数据库设计和关键物理约束示例，不宣称已经部署到某个数据库实例。
