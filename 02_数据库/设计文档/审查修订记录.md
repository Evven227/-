# 数据库设计审查修订记录

## 已发现并修正

1. 原模型将预约、排班、改约时间写成 `TIME`，可能丢失日期信息；现改为 `DATETIME`。
2. 创建、审核、签到、付款和审计事件改用 `TIMESTAMP`；资质和绩效周期仍使用 `DATE`。
3. 绩效快照增加 `calculation_version` 和 `calculated_at`，并将指标口径版本纳入唯一键，可以保留同一周期的不同计算版本。
4. 绩效增加计数一致性约束：到诊、取消、未到诊不超过预约数，完成就诊不超过到诊数，评分不能为负数。
5. 所有枚举字段补充允许值，另建 `status_dictionary.md`，避免只写 `ENUM` 而没有业务语义。
6. 将物理方言确定为 PostgreSQL 18，明确当前交付是逻辑设计和建表基线，不冒充已部署数据库。
7. 增加需求追踪、OpenDental 映射、类型语义和校验说明，便于老师检查需求、表和关系是否对应。
8. 物理数据库改为 PostgreSQL 18，采用 identity 主键，不使用 UUID。
9. 绩效评分确定为 40% 到诊率、40% 完成率、20% 工作量达成率的加权 KPI 方法，并补充奖励等级阈值。

## 已确定的实现基线

- 部署目标为 PostgreSQL 18；当前本机实例已确认是 PostgreSQL 18.6；
- 单字段 ID 使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`，不使用 UUID；
- 预约时间区间冲突采用 PostgreSQL 事务、行锁和服务层校验组合处理；
- 绩效评分采用到诊率 40%、完成率 40%、工作量达成率 20% 的加权 KPI；
- 当前仍待完成的是在本机 PostgreSQL 实例执行全量建表脚本、导入演示数据并运行业务测试。
