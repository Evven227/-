# ADC 牙科诊所数据库设计需求基线

## 1. 目标

建立支持多诊所运营的统一逻辑数据库，连续识别患者，按牙医资质和排班匹配预约，保存可追溯的就诊与治疗事实，并用这些事实支持患者结算、收款、库存数量管理和运营绩效统计。

## 2. 设计范围

数据库覆盖患者档案、过敏史、诊所与人员、牙医资质、预约及预约事件、排班与调班审批、到诊与就诊、治疗项目及价格版本、结算与患者收款、耗材数量库存、权限审计和牙医运营绩效。

## 3. 业务事实原则

1. 预约不得直接删除，改约和取消通过状态与事件保留历史。
2. 同一患者跨诊所使用统一主索引。
3. 预约必须关联患者和已发布排班；排班必须关联牙医和诊所。
4. 到诊后才能形成就诊，治疗完成且明细确认后才能生成结算单。
5. 结算单允许更正版本；收款支持部分支付和唯一凭据。
6. 本项目不包含退款，不建立退款流水。
7. 统计指标优先由预约、就诊和治疗事实计算；周期关闭时可保存牙医绩效结果快照。
8. 绩效结果只包含工作量、到诊、取消、未到诊、评分和奖励等级，不包含工资、利润、成本或奖金支付。

## 4. 参考资料使用边界

OpenDental 26.2 XML 用于参考表的职责划分、历史轨迹、外键关系和多诊所建模方式。OpenDental 的保险、理赔、会计、支付计划、处方、影像和教学评价模块不属于当前 ADC 范围。

## 5. 验收标准

- 总图完整展示 33 张表，每张表只定义一次。
- 每张表至少显示中文名称、英文表名、字段、PK、FK 和关键 UQ。
- 患者—预约—就诊—治疗—结算—收款主链路可追踪。
- 排班、牙医资质和跨诊所执业关系可追踪。
- 预约改约、取消、调班影响和审计事件不会覆盖历史事实。
- 总图、数据字典、SQL 和需求追踪中的表名保持一致。
- 绩效模块不出现工资、成本、利润、奖金支付或会计分录。
- 时间字段区分 `DATE`、`DATETIME` 和 `TIMESTAMP`，预约与排班不得只保存纯时间。
- 所有 `ENUM` 字段都必须在状态字典中列出允许值。
- 物理数据库以 PostgreSQL 18 为目标，单字段 ID 使用 identity，业务时区为 Asia/Shanghai。
- 绩效得分采用加权 KPI 公式，并保存计算口径版本。
